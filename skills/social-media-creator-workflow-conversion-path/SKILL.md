# Creator Conversion Path

把已确认的内容、主页、评论区、私信和产品/服务行动串成一条可检查的用户路径。
目标是减少决策阻力，不承诺成交或替平台执行真实动作。

## Context

先读取账号定位、目标用户、产品/服务、价格与交付、用户顾虑、现有主页和转化目标，
再完整读取 `../../knowledge/skill-packs/conversion-path.md`。

## Workflow

1. 明确终点是体验、反馈、私信、预约、购买还是其他已授权动作。
2. 画出当前路径：内容触达 → 主页承接 → 信任/筛选 → 行动入口 → 私信或外部页面。
3. 找到最早且证据最强的断点，不平均改造所有环节。
4. 为吸引、信任、筛选和行动分别指定内容任务，不让单篇内容承担全部说服。
5. 给主页、置顶、评论和私信各一个清楚职责，并写出私信筛选问题。
6. 检查资格、价格、效果、隐私、平台规则和无法兑现的承诺。
7. 输出最先应改的一处和可观察指标；需要具体文案时交回对应写作或分发专家。

## Deliverables

- 当前路径与断点
- 用户决策阻力
- 内容与主页分工
- 评论/私信筛选动作
- 最小改动与验证指标

## Boundaries

- 不承诺成交率、涨粉、平台推荐或收入结果。
- 不编造用户证明、优惠、库存、名额和产品能力。
- 不把免费工具强行写成购买漏斗。
- 只改主页简介或置顶表达时用 `account-audit`；只写评论回复时用
  `community-manager`；真实数据归因用 `strategy-reviewer`。
